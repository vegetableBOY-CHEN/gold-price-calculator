# 开发路线图

> 更新日期：2026-08-03。完成状态以当前仓库代码为准。

## 已完成：基础产品与计算闭环

- [x] Vue 3 + TypeScript 前端和 FastAPI 后端。
- [x] 首页国际、国内、品牌饰品金和金条价格展示。
- [x] SQLite 持久化国内价、品牌价、大盘缓存和门店规则。
- [x] 行情缓存优先读取与后台刷新，外部来源失败时保留最近数据。
- [x] 多品牌价格来源独立刷新，单个来源失败不影响其他品牌。
- [x] 门店规则 CRUD 和默认种子模板。
- [x] 城市、门店或商场名称字段。
- [x] 旧金损耗统一按百分比计算。
- [x] 增金比例动态输入、前后端校验和不足时禁止计算。
- [x] “是否使用旧金置换”开关。
- [x] 旧金“饰品 / 金条”类型选择和旧金购买成本。
- [x] 计算页规则模板完整只读展示，并跳转到规则页修改。
- [x] 多方案创建、复制、比较和最优方案标记。
- [x] 方案浏览器自动保存和分享链接。
- [x] 核心 API、计算逻辑和行情缓存自动化测试。
- [x] Docker Compose、SQLite 持久卷和部署文档。

## 近期：稳定性与可维护性

- [ ] 为前端补充组件和端到端自动化测试。
- [ ] 给行情刷新增加结构化日志、失败原因和监控指标。
- [ ] 将品牌来源配置与抓取策略解耦，便于失效后单独替换。
- [ ] 引入 Alembic，替代继续扩展手写 SQLite 迁移。
- [ ] 增加规则导入、导出和数据备份操作。
- [ ] 明确回收价来源，替换当前 `新金价 × 85%` 的估算兜底。

## 暂缓

- [ ] 修复或更换到期的实时金价 API Token。
- [ ] 在前端恢复实际回收价输入。
- [ ] 规则生效日期和信息来源。
- [ ] 历史金价走势图。
- [ ] 价格提醒。

## 下一阶段：用户级能力

- [ ] 用户注册、登录和会话管理。
- [ ] 门店规则增加用户归属和数据隔离。
- [ ] 系统示例规则与个人规则分层。
- [ ] 用户计算历史、收藏方案和云同步。
- [ ] 分享链接的权限、过期与规则快照机制。

## 长期

- [ ] 更可靠的多源行情聚合和来源健康度。
- [ ] 门店规则社区共享与审核。
- [ ] 黄金价格趋势和购买时机辅助分析。
- [ ] PWA 或小程序。
- [ ] 国际化。

## 明确不做的假设

- 同一品牌不同饰品的工费可能不同，因此不强制用品牌统一工费覆盖方案输入。
- 当前不把缓存行情描述为实时成交价。
- 在用户系统上线前，不把共享规则误称为“个人规则”。
