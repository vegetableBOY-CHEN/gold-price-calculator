# 金饰购买成本计算助手 PRD

> 当前实现版本：0.2
>
> 文档更新：2026-08-03
>
> 状态说明：本文区分“当前已实现”和“后续规划”，以实际代码行为为准。

## 1. 产品背景

黄金品牌之间的饰品金价、金条价和工费不同，同一品牌不同门店或不同饰品的工费也可能不同。旧金置换还涉及是否支持金条、是否支持跨品牌、增金比例、损耗和回收计价等条件，用户很难直接判断置换是否比直接购买划算。

产品目标是把行情、门店规则和个人旧金成本放到同一套计算中，帮助用户比较方案，而不是代替门店报价或提供投资建议。

## 2. 核心目标

- 查看国内外大盘以及各品牌饰品金、金条价格。
- 在外部行情暂时不可用时继续展示最近可用数据。
- 支持直接购买与旧金置换两种场景。
- 准确计算旧金损耗、抵扣金额、需补差价、真实成本和真实克均价。
- 严格校验门店的增金和适用范围要求。
- 保存并复用门店规则，支持多个方案横向比较。
- 后续将规则扩展为用户级数据，由用户按实际门店情况维护。

## 3. 目标用户与典型场景

目标用户是准备购买金饰、以旧换新或比较多个门店方案的消费者。

典型流程：

1. 在首页查看品牌价格和更新时间。
2. 创建一个或多个购买方案。
3. 填写新金重量、金价和该饰品实际工费。
4. 决定是否使用旧金置换；如使用，填写旧金类型、品牌、重量和原购买成本。
5. 选择门店规则模板，或使用一次性的自定义规则。
6. 系统先检查适用范围和增金条件，再计算成本。
7. 对比多个方案的真实克均价和置换节省金额。

## 4. 当前已实现功能

### 4.1 首页行情

首页展示：

- 国际大盘行情。
- 国内大盘行情。
- 品牌饰品金价、金条价、饰品溢价和更新时间。
- 行情来源、涨跌、刷新周期和“实时 / 缓存 / 兜底”状态。

数据策略：

- 页面默认每 5 秒请求一次行情概览。
- API 先从 SQLite 返回最近缓存，不同步等待第三方接口。
- 每次读取后由后台任务尝试刷新大盘行情。
- 品牌价格默认每 8 小时检查刷新一次。
- 单个品牌来源失败不会阻止其他品牌更新。
- AllTick Token 缺失或到期时，仍保留数据库缓存、国内来源和品牌来源；实时状态可能退化为缓存或兜底。
- 支持通过 API 手动维护国内价格和品牌价格。

### 4.2 成本计算页面

计算流程分为三步。

#### 第一步：新金信息

| 字段 | 说明 |
| --- | --- |
| 新金品牌 | 从当前品牌价格列表选择 |
| 新金重量 | 单位 g，必须大于 0 |
| 金价 | 单位元/g，可按实际门店价格修改 |
| 工费方式 | 按克或按件 |
| 工费 | 当前饰品的实际工费，允许不同饰品填写不同数值 |

#### 第二步：旧金置换

- 使用“是否使用旧金置换”开关控制整个旧金区域。
- 关闭时按直接购买计算，不要求填写旧金信息。
- 开启时展示以下字段：

| 字段 | 说明 |
| --- | --- |
| 旧金类型 | 饰品 / 金条 |
| 旧金品牌 | 可选择与新金同品牌或其他品牌 |
| 旧金重量 | 单位 g，必须大于 0 |
| 旧金购买成本 | 用户当初购买旧金的实际总成本 |

不在页面恢复“实际回收价”输入。后端仍保留可选回收价字段，当前前端按规则自动计价。

#### 第三步：门店规则与计算

- 可选择已保存的规则模板。
- 选择模板后，只读展示模板名称、城市、门店或商场、适用范围、增金要求、损耗、工费和旧金计价方式。
- 计算页面不允许修改已保存模板，仅提供“去规则管理修改”入口。
- 勾选“自定义规则”后，模板选择被禁用，改为填写本方案临时规则；临时规则不会修改数据库模板。
- 自定义规则按勾选项动态展示补充字段。例如勾选“要求增金”后才展示增金比例。
- 增金要求未达到时，计算按钮不可用，并提示要求比例、最低新金重量和当前实际比例。

### 4.3 多方案与分享

- 新增、复制、重命名和删除方案。
- 分别计算单个方案，或一次计算全部方案。
- 按不含工费的真实克均价标记当前最优方案。
- 方案输入自动保存到浏览器 `localStorage`，刷新页面后恢复。
- 可复制包含当前方案输入的分享链接。
- 分享链接和本地存储不包含服务端账户数据；当前尚无用户登录体系。

### 4.4 门店规则管理

规则页面支持新增、编辑、删除和查看模板。

规则字段：

| 分类 | 字段 |
| --- | --- |
| 基本信息 | 模板名称、品牌、城市、门店或商场名称 |
| 适用范围 | 支持金条、支持跨品牌、支持旧饰品 |
| 增金 | 是否要求增金、增金比例 |
| 损耗 | 旧金每克损耗百分比 |
| 工费 | 固定工费 / 按克收费及数值 |
| 旧金计价 | 按回收价 / 按饰品价 |

当前按需求不记录生效日期和信息来源。

## 5. 业务规则与计算公式

### 5.1 规则适用性

使用旧金时，系统必须检查：

- 旧金是金条时，模板是否支持金条。
- 旧金品牌与新金品牌不同时，模板是否支持跨品牌。
- 旧金是饰品时，模板是否支持旧饰品。

任一条件不满足，后端返回明确错误并拒绝计算。

### 5.2 增金校验

```text
最低新金重量 = 旧金重量 × (1 + 增金比例 ÷ 100)
实际增金比例 = (新金重量 - 旧金重量) ÷ 旧金重量 × 100%
```

只有 `新金重量 >= 最低新金重量` 时才允许计算。勾选“要求增金”时，增金比例必须大于 0；取消勾选后比例统一归零。

### 5.3 旧金损耗

旧金损耗只使用百分比类型，含义是每克旧金损耗相同比例：

```text
损耗重量 = 旧金重量 × 损耗百分比 ÷ 100
可抵扣重量 = max(0, 旧金重量 - 损耗重量)
```

示例：10g 旧金、损耗 2%，损耗重量为 0.2g，可抵扣重量为 9.8g。

### 5.4 旧金抵扣

```text
旧金抵扣金额 = 可抵扣重量 × 旧金计价
```

- “按饰品价”：使用当前新金单价。
- “按回收价”：当前前端未输入实际回收价时，计算引擎暂按新金单价的 85% 推算。

这是当前实现的估算规则，后续如接入可靠回收价来源，应替换该兜底算法。

### 5.5 工费

计算页填写的是当前饰品的实际工费，优先于模板工费：

```text
按克工费总额 = 每克工费 × 新金重量
按件工费总额 = 固定工费
```

规则模板仍保存工费规则，供模板说明和后端直接调用时使用；前端方案允许不同饰品填写不同工费。

### 5.6 成本结果

```text
新金总价 = 新金重量 × 新金单价
直接购买成本 = 新金总价 + 工费
需补差价 = 新金总价 + 工费 - 旧金抵扣金额
真实成本 = 旧金购买成本 + 需补差价
置换节省 = 直接购买成本 - 真实成本
真实克均价 = (真实成本 - 工费) ÷ 新金重量
```

真实克均价不含工费。未使用旧金时，旧金重量、旧金成本和旧金抵扣均为 0。

## 6. 页面信息架构

### 首页 `/`

- 行情状态栏。
- 国际与国内大盘卡片。
- 品牌饰品金和金条价格表。
- 手动刷新与进入计算页面的入口。

### 计算页 `/calculate`

- 新金信息。
- 旧金置换开关及条件字段。
- 模板选择、模板只读详情或自定义规则。
- 当前方案结果与多方案比较。

### 规则页 `/rules`

- 规则列表。
- 新增、编辑和删除规则。
- 城市与门店或商场信息。

## 8. 验收标准

- 首页在外部行情请求失败时仍能返回并展示数据库中的品牌价格。
- 行情概览读取不应同步阻塞在第三方网络请求上。
- 一个品牌刷新失败时，其他品牌仍可更新。
- 旧金损耗按 `旧金重量 × 百分比` 计算。
- 未开启旧金置换时可以不填写旧金字段并正常计算。
- 开启旧金置换时必须填写大于 0 的旧金重量。
- 要求增金时，比例必须大于 0；新金重量不足时前后端均拒绝计算。
- 规则模板保存城市和门店或商场名称。
- 计算页的模板详情不包含可编辑输入控件，并能跳转到规则页修改。
- 前端生产构建通过，后端自动化测试通过。

## 9. 非功能需求

| 项目 | 要求 |
| --- | --- |
| 前端 | Vue 3 + TypeScript，支持桌面与移动端 |
| 后端 | FastAPI + Pydantic + SQLAlchemy |
| 数据库 | SQLite，Docker 环境使用持久卷 |
| 响应策略 | 行情概览优先读缓存，避免第三方网络阻塞页面 |
| 数据安全 | Token 只通过环境变量配置，不写入代码和文档 |
| 可验证性 | 核心计算、API、规则 CRUD 和行情缓存具备自动化测试 |

当前规则和金价写接口尚无登录鉴权，只适合受信任环境；用户系统上线时必须同时增加后端授权校验。
